# 2dimg2motion (Улучшенный пайплайн покадровой анимации)

Навык превращения одного статичного 2D-изображения (персонаж, оружие, монстр, предмет) в консистентную покадровую игровую анимацию (14-кадровый цикл: спрайтшит, прозрачные RGBA PNG кадры, превью GIF).

> [!NOTE]
> В оригинальном репозитории генерация кадров полностью возлагается на мультимодальную модель (`image_gen`), а локальный код отвечает за строгую геометрию, центрирование и постобработку. В нашем прокачанном варианте примитивный Chroma Key заменен на интеграцию с высокоточным скиллом `sprite-cutter` (alpha un-matting без потери пикселей и ореолов).

---

## 1. Архитектурный каркас (14-кадровая схема)

Для анимаций удара, бега, магии или прыжка используется жесткий скелет из 6 опорных точек:
`00 -> 02 -> 05 -> 08 -> 11 -> 13` с интерполяцией шагов `1 / 2 / 2 / 2 / 1`.

| Индекс | Роль кадра | Правило построения |
|---|---|---|
| **00** | Исходная стойка (Baseline Start) | Точный исходник, отцентрированный на квадратном холсте с полями |
| **01** | Фазовый переход (In-between) | Интерполяция между 00 и 02 (начало замаха/движения) |
| **02** | **Ключевой кадр 1 (Anticipation)** | Первый опорный кадр: замах, приседание, концентрация силы |
| **03-04** | Фазовые переходы (In-betweens) | Разгон движения от замаха к точке удара (хронологический порядок) |
| **05** | **Ключевой кадр 2 (Contact / Peak)** | Второй опорный кадр: кульминация, выпад, удар, самый широкий силуэт |
| **06-07** | Фазовые переходы (In-betweens) | Инерция удара (Follow-through / Hold) |
| **08** | **Ключевой кадр 3 (Overshoot / Release)**| Третий опорный кадр: спад напряжения, завершение траектории |
| **09-10** | Фазовые переходы (In-betweens) | Возврат тела в боевую стойку |
| **11** | **Ключевой кадр 4 (Recovery)** | Четвертый опорный кадр: стабилизация баланса перед исходной позой |
| **12** | Фазовый переход (In-between) | Доводка конечностей до нулевой точки |
| **13** | Замыкание цикла (Baseline End) | Побайтовая копия кадра `00` для идеального бесшовного зацикливания |

## 2. Золотые правила генерации и топологические замки

### Экранная фиксация конечностей (Screen-Space Topology Lock)
Диффузионные модели склонны перекладывать меч из правой руки в левую при развороте корпуса. Чтобы этого избежать, промпты формулируются строго в экранных координатах (`screen-left` / `screen-right`), а не анатомических:

```text
coordinateSpace: screen-space.
weaponHand: screen-right hand remains the weapon hand in every single frame.
emptyHand: screen-left hand remains empty, counterbalance, never touches or holds the weapon.
activeArm: always originates from the screen-right shoulder even when crossing the torso.
Do not mirror the character. Do not swap hands.
```

### Генерация ключевых поз единым листом (Shared Key-Pose Sheet)
**Категорический запрет:** никогда не генерировать ключевые кадры `02`, `05`, `08`, `11` отдельными запросами! При независимых вызовах модель накапливает дрейф стиля (меняется толщина обводки, длина меча, черты лица, оттенки брони).

Все 4 ключевые позы генерируются **внутри одного изображения за один вызов генератора** в виде горизонтальной полосы из 4-5 ячеек:
- Если модель не поддерживает жесткий референс: первой ячейкой рисуется `Reference Identity Cell` (копия кадра 00 для визуальной сверки моделью), а последующие 4 ячейки - кадры `02, 05, 08, 11`.
- Ячейка 0 (референс) используется только для контроля и отбрасывается при экспорте.

### Фиксация линии опоры (Stable Foot Baseline)
- Персонаж не масштабируется покадрово. Запрещено центрировать каждый кадр по отдельности через авто-фит: это вызывает дрожание спрайта (scale popping).
- Нижняя линия стоп (`foot baseline`) остается строго на одной высоте по Y во всех кадрах.
- При ударе расширяется силуэт холста (safety margins 65-85%), но сам масштаб тела не меняется.

## 3. Сквозной пайплайн выполнения

1. **Подготовка исходника (`standardize_baseline.py`):**
   Масштабирование исходного персонажа до 300-400 px по большей стороне, помещение в центр квадратного холста с запасом полей под размах удара.
2. **Формирование промпта ключевых кадров:**
   Фиксация неизменяемых атрибутов персонажа + описание 4 ключевых поз с таймингами атак (см. `references/motion-patterns.md`).
3. **Генерация листа ключевых поз:**
   Вызов генератора изображений (`generate_image` или ComfyUI) на нейтральном или зеленом фоне.
4. **Удаление фона и нарезка:**
   Применение `sprite-cutter` (чистый альфа-канал без ореолов) вместо сырого Chroma Key. Нарезка ячеек с проверкой отступов (gutters).
5. **Генерация фазовых кадров (In-betweens):**
   Генерация промежуточных кадров двумя пачками (01, 03, 04, 06) и (07, 09, 10, 12).
6. **Сборка и валидация (`fullframes_to_gif.py`, `validate_14frame_pattern.py`):**
   Проверка идентичности кадров 00 и 13, сборка спрайтшита и GIF-превью.
